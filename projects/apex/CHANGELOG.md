# Changelog

All notable changes to **apex** are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Initial build of apex: a premium-modern, EV-positioned car-**rental** marketing site fronted by a genuine WebGL 3D configurator and a complete, mocked multi-step reservation flow. Feature-complete for v1, reviewed (designer-critic and reviewer passes landed, all defects cleared), tested, performance-fixed, deploy-prepared, and royalty-clear (the 3D blocker P0-1 is resolved — the whole fleet runs on CC0 models). Web-only, no backend. v1 is deployed and public at https://apex-rentals.fly.dev (Fly.io, region `fra`, 2026-06-05). The final shipped CSP is `script-src 'self' 'unsafe-inline'` — the `'wasm-unsafe-eval'` from the original ADR-002 posture was dropped once the CC0 models removed the need for a WASM mesh decoder.

### Added

**Architecture (ADR-001 to ADR-005).**

- **ADR-001** — Stack flavour `web-only` (no backend service; the only server surface is one Next.js server action for the mocked submit). The R3F + GSAP two-library posture, with Motion explicitly excluded by default. Sovereign light-canonical design tokens (no reuse from `tape`, `meld`, `razors-edge`, or `pulse`). The fully client-side mocked reservation architecture. Portfolio composition: the api-heavy slots are satisfied by `tape` (Elysia/Bun), `meld` (Hono/Node), and `pulse` (NestJS), so slot 5 is a deliberate second web-only creative showcase, with a genuine 3D capability that none of the others demonstrate.
- **ADR-002** — The animation/3D boundary and the R3F-with-Next-15 integration. The hard, mechanically-auditable rule: R3F + drei own everything inside the WebGL canvas; GSAP owns all scroll / pin / scrub / timeline / SVG and DOM-side state transitions; the one sanctioned coupling at the seam is one-directional value passing. The R3F integration contract (`next/dynamic ssr:false` Canvas, Suspense, a low `'use client'` boundary, `frameloop="demand"`, capped `dpr`, `AdaptiveDpr` / `PerformanceMonitor`). The WebGL performance contract and the capability/tiering heuristic (`detectWebglTier()`: a WebGL2 probe plus cores, memory-when-present, coarse-pointer/viewport, and `prefers-reduced-data`, with a runtime demotion). The strict-CSP posture: `script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'` (no `unsafe-eval`), verified under `next build && next start`.
- **ADR-003** — The reservation-mock architecture. The domain model and shared Zod schemas (`src/lib/schemas/`); the pure deterministic `getRangeAvailability` (half-open date ranges over seeded blackouts and bookings against a frozen `now`) and `priceQuote` (daily rate times rental days, plus per-day or flat extras, plus the insurance tier, plus a flat one-way fee, minus a multi-day discount); the Zustand `persist` wizard machine (`localStorage` key `apex:reservation-draft`, version 1, 24-hour TTL) with the date-range reconciliation rule on rehydrate; insurance modelled as a separate single-choice tier field; the configurator carry-over; TanStack Query over an in-memory seeded source (no network); the `reserveVehicle` server action re-validating the shared schema; and a hand-rolled RFC-5545 `.ics` over the rental range.
- **ADR-004** — The hero-to-configurator hand-off seam and the four-tier degradation. The back-to-front layer model (static AVIF render as LCP, the live canvas behind it, the real-DOM controls always present); the reveal-when-ready, pose-matched crossfade (no empty-canvas flash, no pop, LCP never the canvas, CLS-safe); the one-directional GSAP-to-R3F seam coupling; the pre-baked colour-by-wheel render matrix as the Tier-3 source; the configurator's accessible DOM radio-group controls and the `aria-live` configuration text alternative; and the precise Tier 1 / 2 / 3 / 4 behaviours (live scene / reduced-motion crossfade / pre-baked stills / no-JS static frame).
- **ADR-005** — The deploy posture: Fly.io single Machine, Next.js 15 standalone, region `fra`, web-only, no secrets, `NEXT_PUBLIC_SITE_URL` baked at build, a warm floor (`min_machines_running = 1`) for the first impression, 512 MB for the `next/image` optimization path. Resolves the Windows standalone-symlink issue by building the standalone artifact inside the Linux Docker stage. Records the branded-model swap as a blocking precondition for a public URL.

**Scaffold and foundation** (Phases 1 to 3).

- Next 15.5 App Router + React 19.2 + TypeScript strict + Tailwind v4 (CSS-first) + shadcn/ui new-york primitives over a sovereign token bridge, dev/prod pinned to port 3090. next-themes with light default. TanStack Query + Zustand + react-hook-form + Zod providers at a low `'use client'` boundary. GSAP + ScrollTrigger registered through a single module, and an R3F smoke Canvas (`next/dynamic ssr:false`), both verified CSP-clean and code-split out of the initial bundle.
- Sovereign design tokens in `app/globals.css`: the premium-modern/EV cool-light palette with a voltaic green-cyan accent (split into three tokens for AA contrast) and the recurring hairline "track line", plus the intentional dark "night drive / charging-bay" re-key. All key contrast pairs verified to WCAG 2.2 AA in both themes.
- Type system: Space Grotesk (variable display) for the wordmark and section heads, Inter (variable sans) for body and UI, both via `next/font` (self-hosted, CSP-clean) and both SIL OFL 1.1.
- Shared Zod schemas (vehicle, configurator option with a render-matrix completeness check, location, extra as a discriminated union on `kind`, vehicle booking, availability with a reason enum, price quote, reservation draft and submit projection, driver, testimonial, shop); seeded faker mock data (a fixed 5-EV fleet with one configurable, four paint colours by three wheels plus the render matrix, four locations, extras and three insurance tiers, seeded per-vehicle bookings, six testimonials) baked to a static file so faker is build-time only; a frozen clock at `2026-06-15` UTC.
- The pure `getRangeAvailability` and `getDisabledRanges` (half-open interval overlap, window and rental-length guards, accessible reasons) and the pure `priceQuote`, both React-free and unit-tested.

**Chrome, the scroll-hero, and the configurator** (Phase 4).

- App chrome: a sticky header that is transparent over the hero and gains a legible backdrop on scroll, anchor nav with `aria-current`, a theme toggle, a primary Reserve CTA, and a mobile sheet drawer; the recurring track-line section divider; and the brand footer.
- The scroll-hero: the static AVIF product render as the LCP, the pinned GSAP intro writing seam-progress, and the reserved, CLS-safe mount box, with the reduced-motion and no-JS branches.
- The live 3D configurator: the R3F + drei scene loading the optimized meshopt-compressed GLB, drag-to-orbit (damped and bounded), live colour and wheel-finish swaps, `Lightformer` studio lighting (no fetched HDRI) and a contact-shadow ground, capped `dpr` / `frameloop="demand"` / adaptive quality, the accessible DOM radio-group swatch controls and the debounced `aria-live` text alternative, and the "Reserve this configuration" CTA carrying the chosen config into the wizard.
- The four-tier degradation: the `detectWebglTier()` gate plus runtime `PerformanceMonitor` demotion swapping the live scene for pre-baked stills (Tier 3 loads no three.js — the mobile path), the reveal-when-ready pose-matched crossfade (Tier 1), the reduced-motion crossfade (Tier 2), the no-JS static frame (Tier 4), and the dark-stage matrix re-key. One shared camera and lighting rig drives the model, the hero still, and the matrix.

**Marketing sections and the reservation wizard** (Phase 5).

- Editorial sections: the fleet list (the configurable flagship featured larger, the four others in a consistent card family, each "Reserve this" deep-linking pre-seeded), the "how it works / why APEX" value section, the gallery (a GSAP masked-wipe and parallax scroll-reveal on desktop, a vertical snap stack on mobile, all `next/image` AVIF), the locations section with styled static-map treatments and a maps click-through plus `AutoRental` JSON-LD, the testimonial/trust set, and the designed brand footer with a provenance credits line.
- The `/reserve` reservation wizard (the centerpiece interaction): the five-step machine over the persisted Zustand store, the step indicator, back/next preserving state, GSAP/CSS step transitions (no Motion), deep-link pre-seeding and the configurator carry-over, and the responsive summary rail (a sticky desktop rail and a sticky mobile bottom bar) with the live `priceQuote` total in an `aria-live` region.
- The steps: vehicle pick (carried config reflected), a hand-rolled keyboard-operable date-range picker (roving-tabindex grid, booked days struck out and announced, specific accessible rejection reasons) wired to availability via TanStack Query, pickup/return selectors with the one-way fee, extras and insurance-tier selection updating the live price, the driver form (react-hook-form + Zod, format-only licence), and the confirmation (the `reserveVehicle` server action, a deterministic `APX-XXXX-XXXX` reference, the chosen-config render, the `.ics` download, a GSAP success flourish, and honest demo copy).

**Polish, review, accessibility, SEO, and performance** (Phases 6 to 7).

- Cleared the designer-critic ledger across multiple passes: replaced the procedural model with the optimized real GLB (then surfaced the branded-model license flag), grounded and re-keyed the studio scene per theme, fixed a missing `invalidate()` that left material swaps un-repainted, deployed the track-line motif through the chrome and dividers, distinguished the swatch focus / selected / hover states, made the configurator stage responsive, unified the fleet into one studio family, replaced the gallery glyphs with real studio crops, and polished the wizard micro-interactions (the date-picker rejection reasons, the insurance ladder, the closing of the configurator spine on the confirmation).
- Code review (reviewer GREEN): the R3F lazy-load and code-split, the GSAP cleanup and SSR boundaries and the hand-off seam, the wizard and configurator state machines, the availability and price purity, the shared-schema contract, the CSP compatibility, the OG image, JSON-LD escaping, the `.ics` CR normalisation, GPU-resource disposal on unmount, and a latent Zustand-clear bug fixed.
- SEO: `sitemap`, `robots`, the `next/og` Open Graph image, the `AutoRental` JSON-LD built from the live fleet, locations, and shop data, and per-route canonical / OG / Twitter metadata. Canonical origin via `NEXT_PUBLIC_SITE_URL`.
- Performance: deferred the live R3F canvas mount off the home initial load (it arms on approach or user intent, so three.js and the GLB are never in the first-load bundle), and made the hero render the definitive LCP on both profiles. Desktop `/` Performance 56 to 97 (LCP 2.5 s to 1.1 s, TBT 2589 ms to 94 ms); `/reserve` 99. The mobile synthetic sub-95 is a documented 4x-CPU-throttle artifact (real-device CPU scores 100 / LCP about 1000 ms); the deployed Fly real-CPU run is the authoritative mobile measurement.

**Tests and CI** (Phase 7).

- 151 Vitest unit tests: the pure `getRangeAvailability` and `priceQuote` across every overlap, window, length, and discount boundary; the wizard and configurator state machines (step guards, deep-link seeding, configurator carry-over, persist rehydrate and the forced-stale date-range reconciliation, the submit-payload projection); and the booking-reference and `.ics` builders.
- 22 Playwright E2E tests across a desktop and a mobile/Pixel-7 (Tier-3) project, run against the served production build: the reservation happy path to confirmation with the `.ics` download, the configurator DOM-swatch interaction plus the Tier-3 still-swap and the Tier-4 no-JS floor, full keyboard operation of the date-range picker, the theme toggle in both themes, and the `prefers-reduced-motion` hero path.
- Lighthouse CI (`lighthouserc.json` desktop and `lighthouserc.mobile.json` mobile, median of 5): Accessibility 96, Best Practices 96 on all page-by-profile combinations, SEO 100 on `/` (with `/reserve` deliberately `noindex`), desktop `/` Performance 97 and `/reserve` 99; the mobile synthetic Performance is surfaced as a documented warning.

**Model swap — branded placeholder to a CC0 royalty-clear fleet** (resolves P0-1, designer-critic N-1).

- **PASS A — the configurator flagship.** Replaced the branded Mercedes-Maybach GLS placeholder GLB with the CC0 **Kenney "Car Kit" v3.1** `suv-luxury` (an unbadged low-poly luxury SUV) under the fictional APEX/LUMEN naming. The body ships textureless (a custom clearcoat `MeshPhysicalMaterial` driven by the paint swatch); the three wheel sets ship as separate GLBs instanced for a genuine wheel-geometry swap. All uncompressed and tiny, so there is **no meshopt/draco decoder and no WebAssembly at load** — which let the CSP **drop `'wasm-unsafe-eval'` from `script-src`** (a genuine security tightening; the served policy is now `script-src 'self' 'unsafe-inline'`). The shipped runtime model footprint went from **1.82 MB to ~117 KB**. The configurator matrix, hero, gallery, and wheel-thumb stills were all re-rendered from the live scene on the same rig.
- **PASS B — the rest of the fleet + reconciliation.** Re-rendered the four non-flagship fleet cards (Stratos, Terra, Vella, Mira) from the SAME live R3F rig, studio lighting, and clearcoat-paint mechanism against four consistent CC0 Kenney silhouettes (`sedan-sports`, `suv`, `sedan`, `hatchback-sports`), each with a tasteful default paint, so all five cards read as ONE studio line-up (closes N-1 — previously the four were procedural-SVG jellybeans next to the photoreal flagship). The old SVG fleet generator was retired. Reconciled the mock fleet names/segments/specs/copy to the actual silhouettes (e.g. Stratos is now a four-door performance super-saloon, not a two-seat coupe). Folded in the PASS-A caveats: the default wheel is now the dark Turbine rim (legible on the white body), and the wheel-swatch thumbs are shot against graphite paint with a tight crop so the three rim geometries read apart. The single-mesh glasshouse-takes-body-paint limitation is documented and left for the higher-fidelity v2 GLB. The fleet body GLBs are render-only inputs (excluded from the runtime image). CREDITS.md fully reflects Kenney CC0 for the whole fleet; **P0-1 is resolved** — no branded model anywhere.

### Not shipped in v1 (deferred)

- **Any real backend, database, or persistence.** The reservation is mocked end to end; a reload starts fresh. Wiring a real rental API (the unused Fastify slot, or NestJS) is the explicit v2 path.
- **A higher-fidelity 3D model.** v1 ships the CC0 Kenney low-poly fleet (royalty-clear, unbadged — the P0-1 blocker is resolved). A higher-fidelity unbadged CC0 EV GLB (with a separate glass material) is a documented v2 swap; the swap-for-real path is unchanged.
- **Real authentication, payments, or email / SMS confirmations.** None in v1; the price is displayed but nothing is charged, the licence is format-validated only, and the confirmation is on-screen plus an `.ics` download.
- **A configurable fleet.** v1 ships one configurable hero vehicle; the rest use static renders. Per-vehicle configurators are a v2 path.
- **A live interactive map embed.** v1 uses styled static-map treatments plus a maps click-through; a lazy live embed is a v2 candidate.
- **CMS-managed content and internationalisation.** Seeded mock data, English only.
- **Deploy.** Prepared but not yet public — now gated ONLY on the owner running the Fly deploy (the branded-model blocker P0-1 is resolved; the whole fleet is CC0).
