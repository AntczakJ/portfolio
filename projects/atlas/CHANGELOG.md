## [0.1.0] — 2026-06-06

A complete, working live geospatial fleet-tracking console — feature-complete for v1, tested, and deployed to https://atlas-ops.fly.dev (Fly.io, region `fra`). A server-side deterministic simulation engine moves eighteen vehicles along hand-authored Porto routes on a fixed 1 Hz tick; telemetry streams over one `@fastify/websocket` connection; a MapLibre control-room map interpolates the fleet at 60 fps between authoritative ticks (the wow), with route trails, live ETAs, and live geofence enter / exit events. Four graceful-degradation arms, a first-class accessible non-map fleet table, a Lighthouse-100 SEO landing, seven ratified ADRs, designer-critic and reviewer passes applied, and Vitest + Playwright + Lighthouse CI in place. Deployed with a keyless Porto `.pmtiles` vector basemap served same-origin.

### Added

**Architecture (ADR-001 to ADR-007).**

- **ADR-001** — Stack flavour `api-heavy` (three of the five hard triggers fire: a long-lived high-frequency WebSocket, a continuously-running simulation loop, heavy geospatial domain logic). Backend Fastify on Node 22 LTS with @fastify/websocket + Drizzle + PostgreSQL + Zod. Real-time channel WebSocket (not SSE — high-frequency and genuinely bidirectional, the deliberate counterpart to pulse's SSE). MapLibre GL JS keyless-by-default. turf shared FE/BE. The pure deterministic tick reducer. Hand-rolled rAF interpolation for the map plus Motion (single library) for UI chrome. Sovereign control-room tokens, no reuse. Portfolio backend variance completed: Elysia/Bun (tape), Hono/Node (meld), NestJS/Node (pulse), Fastify/Node (atlas) — four distinct backends across four api-heavy projects.
- **ADR-002** — Simulation engine. The pure tick reducer (`tick(state, dt, rng) -> { state, events }`, no wall-clock or IO inside). Two-phase determinism: a `faker.seed` static baseline baked to a module + a seeded mulberry32 PRNG carried in `WorldState` for bounded per-tick jitter. A fixed 1 Hz cadence driven by a fixed-dt accumulator (late wakeups advance whole ticks; demo speed scales ticks-per-second, never the reducer dt; a max-catch-up cap). Cumulative-segment-length projection with a per-tick binary search. The braking-taper + dwell-at-stop speed model. Loop / ping-pong route-end per a `loop_mode` field. In-process, single-instance, no-broker topology.
- **ADR-003** — Real-time WS contract. A single tagged-union JSON envelope `{ t, seq, ... }`: server-to-client `snapshot` / `tick` (ETA + status folded in) / `event` / `heartbeat` (20 s); client-to-server `subscribe` / `unsubscribe` / `snapshot.request` / `sim.control`. JSON encoding (legible DevTools tell at this fleet size; `protocolVersion`-versioned so a binary tick is a clean v2 lever). Server-side subscription scoping with a whole-fleet default. Monotonic-`seq` gap detection with snapshot-resume. Coalesce-to-latest-per-vehicle backpressure (never replay stale motion). Frames Zod-validated jitless at the boundary.
- **ADR-004** — Geo math + geofence detection. Scoped `@turf/*` modules in `atlas-shared/geo`, shared FE/BE. A per-(vehicle, zone) hysteresis state machine (the no-flap invariant: a boundary-skimming vehicle fires no spurious events). ETA from remaining-distance-to-next-stop over a rolling-average speed, clamped at a floor, with dwell folded in. turf units pinned to metres everywhere.
- **ADR-005** — Data model + persistence. Plain PostgreSQL + GeoJSON in `jsonb`; PostGIS rejected for v1 (every read is an ordinary indexed id/time read — PostGIS would be decorative; deferred to v2, the `jsonb` GeoJSON is PostGIS-indexable later). Six-table Drizzle schema (vehicles, routes, route_stops, zones, telemetry_snapshots, events) with the feed indexes and enum types built from the shared Zod tuples. Hand-authored Porto routes / zones inside the demo-city bbox. Bounded retention (periodic snapshot upsert + capped events window). A queued async event sink off the tick hot path.
- **ADR-006** — Map engine + tile source. A single GeoJSON source + symbol layer (`icon-rotate` from a per-feature heading) updated via `setData()` off the React render path. The keyless default: a self-hosted Protomaps `.pmtiles` vector basemap (a deploy artifact) with a painted control-room graticule fallback baked in, plus a purely-additive optional tile key. Two intentional dark / light style JSONs swapped by `next-themes`. A strict CSP with no `unsafe-eval` (`worker-src 'self' blob:` for MapLibre's tile-parse worker, `connect-src 'self'`), verified against a prod build.
- **ADR-007** — Deploy topology. Fly.io: a single warm Fastify machine (WS gateway + in-process engine + REST, single instance, no broker) + Fly Postgres + the Next web. The WS survives the Fly edge via the 20 s heartbeat. A warm floor on the engine machine so the fleet is already moving on first paint. Seed-vs-live coexistence (the frozen baseline is the world definition, the engine ticks forward). The committed-keyless `.pmtiles` served same-origin with HTTP range support; the optional tile key a deploy-only secret.

**Shared** (`atlas-shared`, the FE/BE contract package at the atlas root).

- Phase 1 — The Zod schema barrel (`src/lib/schemas/`): vehicle, route, stop, zone, telemetry tick, event, GeoJSON primitives, shared enums, the WS frame envelope + control frames (`src/lib/schemas/ws/`), and later the REST read responses (`rest.ts`). The cross-package `exports` seam (`atlas-shared`, `/schemas`, `/schemas/ws`, `/geo`) with a `default` condition so drizzle-kit's CJS resolver finds the source. The `z.config({ jitless: true })` early side-effect for the runtime WS validation under the no-`unsafe-eval` CSP.

Scoped `@turf/*`, units pinned to metres, pure and testable — the shared implementation both the engine and the client consume.

### Honest boundaries

- **Server-authoritative sim, client-interpolated motion.** Positions, headings, speeds, ETAs, route progress, and geofence transitions are computed server-side by the seeded engine. The on-screen smoothness is interpolation between authoritative 1 Hz ticks, never faked client motion. This is the credibility line and is documented.
- **Seed vs live.** The `faker.seed` baseline (the fleet, the hand-authored Porto routes, the zones) is the deterministic world definition; the motion is live forward ticks, seekable back via the reducer fold. Postgres stores the definitions, a bounded snapshot, and the events history — it is not the engine's source of truth, which is why the live channel runs DB-less.
- **Keyless map.** The committed repo renders the map with no paid secret (the painted control-room graticule basemap). The self-hosted Porto `.pmtiles` vector basemap is an optional deploy artifact; the optional tile key only enriches the basemap when supplied at deploy.
- **The DB seed runs at deploy, not in CI.** The live WS channel and the public read endpoints run DB-less by design; the persisted events history + reconnect-from-persisted-snapshot want the seed, which ran as part of the Fly deploy.

### Not shipped in v1 (deferred)

- **Real GPS / real telematics ingestion.** v1 is a simulation; the architecture would accept a real ingestor in place of the engine — a v2 extension.
- **Routing / pathfinding / road-snapping** (OSRM / Valhalla / GraphHopper). Routes are hand-authored polylines; real turn-by-turn routing is v2.
- **PostGIS + arbitrary spatial queries** (vehicles-within-radius, spatial-index viewport culling). v1 computes geo in-engine; PostGIS is the v2 upgrade if a real spatial-query feature is added.
- **Multi-tenant / dispatcher accounts / assignment workflows / driver app.** v1 is a single live operations view plus demo control.
- **Real ETA / traffic models.** ETA is remaining-distance over speed; live traffic and time-of-day effects are v2.
- **Long-horizon history / analytics / a playback library.** v1 keeps a bounded telemetry / events window plus the deterministic replay; long-horizon analytics is v2.
- **A configurable geofence rules engine** (dwell-time alerts, speeding-in-zone). v1 fires enter / exit + status; a rules engine is v2.
