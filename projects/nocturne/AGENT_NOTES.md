## Gotchas

- **`data-armed` + the page-overflow lock + the HUD/intro mount key off `isCapabilityFloor`, NOT the RESOLVED route (frontend-engineer, 2026-06-14).** `resolveRenderRoute` maps `motionMode === 'still'` → resolved `'poster'`, so keying the Stage's `data-armed`/overflow-lock/HUD-mount off `route === 'poster'` conflated the CAPABILITY floor (genuine Tier-4: no WebGL2 / no float / software GL — the SSR scrollable directory is the readable surface) with the Still-motion still on a CAPABLE device (the immersive fullscreen stage, frozen to the poster). That conflation caused the reported bug: toggling Still un-hid the SSR directory (scroll returned, wordmark drifted off-centre) and hid the poster (blank stage). FIX: the pure `isCapabilityFloor(config)` = `!config || config.route === 'poster'` is the discriminator (`src/lib/engine/routing.ts`). The Stage drives `data-armed` + `overflow:hidden` + the HUD/intro mount off `isCapabilityFloor` (live, calm, AND still-on-capable all stay scroll-locked + directory-hidden + HUD-up); only the genuine floor unlocks scroll + reveals the directory + the hardware hint. **RULE for downstream: NEVER key the page-chrome lock / SSR-directory reveal / HUD mount off the RESOLVED `route` — use `isCapabilityFloor(config)`. The resolved `route` is for what the STAGE renders (field vs frozen poster), not for what the PAGE does.** Poster visibility is `posterVisible = !(showField && revealed)` (the poster shows whenever the live field is not the visible surface — pre-arm, Still, and the floor all show it; only live+revealed shows the field), so Still is a VISIBLE frozen still, never blank. `fieldReady` resets when the field unmounts (Still) so a Still→Full toggle re-reveals via the poster bridge (no black flash). Toggling Still must NOT touch `armState` (it only sets `motionMode`); the HUD's motion buttons read the store directly so the user can always toggle back. Verifier: `web/scripts/verify-still-toggle.mjs` (Part A capable-device 4× Still toggle assertions; Part B genuine-floor no-regression). Tests: `isCapabilityFloor` in `routing.test.ts` proves `config.route==='poster'` (floor) is distinct from `motionMode==='still'` (resolved poster, capable, NOT floor).
- **SOFTWARE WebGL passes the WebGL2 + float gates — the software gate is the 0%-GPU/100%-CPU fix (frontend-engineer, 2026-06-14).** SwiftShader/llvmpipe/etc. acquire a WebGL2 context AND report `EXT_color_buffer_float`, so without an explicit software check the full 262k GPGPU + bloom runs on the CPU. `detectGpuTier` now has a software gate AFTER the float gate (Step 3b): `isSoftwareRenderer()` reads `WEBGL_debug_renderer_info → UNMASKED_RENDERER_WEBGL` (matched against `SOFTWARE_RENDERER_SUBSTRINGS`, case-insensitive) AND probes a `failIfMajorPerformanceCaveat:true` context (caveat-only ⇒ software). EITHER signal → poster with `posterReason: 'software-webgl'`. The pure combinator is `decideSoftwareRenderer(rendererString, caveatOnly)` (unit-tested, incl. the caveat-null path); `isSoftwareRendererString(s)` is the string matcher. Keep these injectable/pure — they must not touch the GPU at import. **Order matters:** no-webgl2 → no-float → software (a no-float client never reaches the software probe; asserted).
- **`posterReason` is the machine-readable fallback cause; the free-text `reason` is diagnostics copy.** `posterReason` ∈ `'no-window'|'no-webgl2'|'no-float'|'software-webgl'|null` (nullable, `.default(null)` so non-poster configs + tests that omit it still parse — do NOT make it required again, it broke `routing.test.ts`'s `makeConfig`). The hardware-acceleration hint shows ONLY for `software-webgl` (a fixable setting); `no-webgl2`/`no-float` are capability floors and get NO hint.
- **`?tier=` (forceTierConfig) BYPASSES the software gate by design.** It skips the whole probe to force the LIVE field on headless software-GL (so verifiers can check non-poster surfaces). Documented in `forceTierConfig`. The real client path always goes through `detectGpuTier`. Verifiers that want to exercise the software fallback must NOT pass `?tier=`.
- **The per-frame palette texture must be written IN PLACE, not rebuilt (frontend-engineer, 2026-06-14).** `nocturne-field.tsx`'s `useFrame` used to call `buildPaletteData(ramp)` (a fresh `Uint8Array(1024)` alloc) and set `palette.needsUpdate = true` EVERY frame. Now: `writePaletteData(ramp, palette.image.data as Uint8Array)` writes into the existing buffer, and the write + `needsUpdate` happen ONLY when `resolveLook` returns a non-null `ramp` (a cross-fade is active). On idle frames the texture already holds the correct ramp (the last transition frame lands on the target exactly via `easeOutExpo(1)===1`, or the init palette), so both the write and the GPU upload are skipped. If anyone re-introduces an unconditional `needsUpdate = true` or a per-frame `buildPaletteData`, it re-opens the sink. `buildPaletteData` (allocating) is retained for INIT (`buildInitialPalette`) + tests; `writePaletteData` is the hot-path variant (byte-identical output, asserted).
- **DEFERRED: a runtime FPS safety-net demotion to the poster.** The brief floated demoting toward the poster floor if `PerformanceMonitor`/sustained-low-FPS sees a missed software case at runtime. NOT shipped — it needs real-GPU threshold tuning (a legitimately busy real GPU mid-bloom must not be mistaken for software and torn down to the poster), which can't be tuned on headless software-GL. The init-time software detection (FIX 1) is the primary fix and covers the reported case. Revisit only with a real-GPU profile + a conservative sustained-FPS window; keep it OUT of the poster path until then.

- **`EXT_color_buffer_float` is the hard GPGPU gate (ADR-002 §1/§4).** Rendering TO a half/full-float texture is NOT core WebGL2 — it needs this extension. `detectGpuTier()` must check `gl.getExtension('EXT_color_buffer_float') !== null` after acquiring a WebGL2 context; null → Tier-4 poster. This is the very first capability check the frontend-engineer implements (Task 1.3).
- **`GPUComputationRenderer` is `three/examples/jsm/misc/`, not core three** (ADR-002 §1) — version-coupled to the installed three; if a three upgrade breaks it, the documented escape hatch is a hand-rolled two-RT ping-pong. MIT, no extra dep.
- **`MediaElementAudioSourceNode` one-per-element rule (ADR-003 §1):** a second `createMediaElementSource` on the same `<audio>` element THROWS. The built-in track and the upload need **two distinct `<audio>` elements**, each wrapped once. Switching toggles which plays + which source node is connected to the gain.
- **The mic source node must NOT connect to `audioContext.destination`** (ADR-003 §1) — that would feed back / echo the room. Mic path is `MediaStreamAudioSourceNode → analyser` only (the analyser taps without a destination connection). Built-in + upload DO connect to destination (the user hears them).
- **`frameloop="always"` is the deliberate divergence from apex** (which used `demand`). It is REQUIRED (continuous audio-reactive field) but MUST pause when the tab is hidden (`visibilityState`), pre-arm (poster showing), and under the reduced-motion "Still" branch — "always while armed and visible," never burning a hidden tab (ADR-002 §5).
- **Auto-dimming HUD must never drop keyboard reachability / a11y-tree presence** (ADR-004 §5) — dimming is opacity-only; focus brings it back; it stays in the tab order. A known a11y trap; a named reviewer item.
- **Windows standalone EPERM** (inherited portfolio gotcha — see apex ADR-005): the host `next build` can't symlink-trace standalone; the deploy builds the standalone inside the Linux Docker stage. Not a dev blocker, but never ship a host-built `.next`. Relevant at Phase 8.

## Pass-2 facts + gotchas (frontend-engineer, 2026-06-14) — THE ENGINE

Render = `THREE.Points` (`render.glsl`): vertex samples position tex at the once-built `reference` attr, `gl_PointSize` = size×attenuation×sparkle×lifeFade; fragment = additive soft disc, palette-ramp colour. In audio-engine.ts every audible source connects directly to ctx.destination (out/src.connect(ctx.destination)) AND to the master gain; the gain feeds ONLY the analyser. So setMuted(gain=0) silences the analyser feed (field -> idle drift) but the user still HEARS the synth/upload - the inverse of ADR-003 sec 1. Fix: route the audible path through the master gain (gain -> analyser AND gain -> destination; sources -> gain only), keeping mic off destination. Owner: frontend-engineer.
- **Nits (defer):** N1 per-frame raw-band object + pointer-array allocation in the field useFrame (bounded, not per-particle; hoist to refs); N2 Math.random detune in connectSynth (prefer seeded); N3 pointer wake \*3.2 magic scale not preset-relative; N4 redundant freqData init size.
- **Confirmed for downstream:** zero-per-particle-CPU invariant holds; FBO ping-pong + curl correct; teardown leak-free; CSP exact + eval-free + zod jitless guarded on every route; both Pass-2 post/useFrame gotchas honoured; full GPU + audio dispose on unmount; JSON-LD static app-authored only.

## designer-critic critique facts + recurring patterns (2026-06-14)

Critique in `web/docs/critique.md` — 0 blockers / 4 high / 12 total; S14 vs-apex gate = PASS. Captures in `web/docs/critique-shots/`. Recurring patterns the frontend-engineer should pre-empt in this and future milestones:

- **PATTERN — `next-themes` with `defaultTheme="dark"` + `enableSystem` does NOT respect `prefers-color-scheme`.** When you want dark-canonical AND system-respect (CLAUDE.md S4), `defaultTheme` must be `"system"` (with `enableSystem`), not `"dark"`. A hardcoded `defaultTheme` wins over the system probe, so a light-OS visitor gets dark on first load. Verified here via Playwright `colorScheme:'light'` -> `html.dark`. (D-01.) This is the kind of thing the project's own verify scripts did NOT catch because they never asserted the light-OS first-load path — add a `prefers-color-scheme:light` assertion to the verify harness.
- **PATTERN — large display type in a fullscreen overlay needs a viewport-bounded clamp, not the shared `--text-6xl` step.** The intro wordmark uses `--text-6xl` (up to 10.5rem) full-bleed with no `max-width`/no viewport-relative cap, so it overflows both edges at 390px and reads as clipped (D-02). The SSR Tier-4 hero, by contrast, sits inside a `max-w-2xl` scrim card and is fine — the difference is the container. Overlay headlines need their own `clamp(min, vw, max)` sized to fit the narrowest viewport.
- **PATTERN — display tracking should DECREASE at large sizes.** `--tracking-wider: 0.28em` is right for the small spaced HUD micro-label but wrong for the hero lockup (fragments it). Don't reuse the spaced-label tracking token on display type (D-06).
- **PATTERN — text over the live field is a contrast hazard at PEAK bloom, not average.** The scrim (`--stage-scrim` 62% near-black) holds AA over an average field but FAILS (~2.2:1 reasoned) when an additive preset (molten/solar-wind) blooms toward white behind the HUD bar (D-04). Tune scrims/text-shadows for the worst-case bloom, and verify against the hottest preset, not the calm default. `--stage-scrim-strong` already exists for exactly this — wire it to the bottom control bar.
- **PATTERN — the field cross-fade is the signature transition and must be eased.** `tr.t += dt/CROSSFADE_SECONDS` is linear (`nocturne-field.tsx:425`); the project owns `--ease-out-expo` but only applies it to CSS HUD reveals, never to the field morph (D-03). Any uniform interpolation that a viewer watches (preset morph, poster->live reveal) should run through an easing function, not raw `t`.
- **NOTE — the engine wow is judged "credible by construction" only.** Headless SwiftShader mutes colour and cannot hit 60fps, so the final arresting-ness of the field (true palette saturation, audio-pulsed bloom, frame rate) is NOT verified by this critique and remains the doc-writer's GIF-capture + the real-GPU deploy to confirm. The palette SET (read from `presets.ts`) is rich and distinct — that part is verified from source.
