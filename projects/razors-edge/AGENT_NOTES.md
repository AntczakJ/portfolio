## Gotchas

- **Animation boundary rule (ADR-002) — memorise it.** **Scroll/pin/scrub/timeline/SVG = GSAP. React-state component enter/exit = Motion. Hover/active/theme-crossfade = CSS.** Motion's `useScroll`/`useTransform` are **banned** in this project. No React-state transition is authored in GSAP; no scroll work is authored in Motion. The reviewer enforces this mechanically in Phase 5. Two libraries is a deliberate, bounded exception to the § 15 single-library default — still contestable: if Motion earns its bundle nowhere but the wizard, raise collapsing to GSAP-only (preferred end state) in this file at Task 4.5.
- **All GSAP goes through `useGSAP()` from `@gsap/react` (ADR-002).** Never raw `useLayoutEffect` + `gsap.context()`. Pass a `scope` ref and `dependencies`; cleanup (revert of animations + ScrollTriggers) is automatic and StrictMode-double-invoke-safe by construction. Register plugins once in a single `'use client'` module (`gsap.registerPlugin(ScrollTrigger, useGSAP)`); never import ScrollTrigger into a Server Component. Reduced-motion + responsive branching is `gsap.matchMedia()` inside the `useGSAP` callback — never an ad-hoc `window.matchMedia` read.
- **CSP posture is fixed (ADR-002) — set it in Task 1.1, verify it in Task 1.3.** Production: `script-src 'self'`, **no `unsafe-eval`** (GSAP core + ScrollTrigger + `@gsap/react` do not need it), and `style-src 'unsafe-inline'` is **expected and accepted** (Next/Tailwind inject inline styles; GSAP writes inline `style` transforms that CSP `style-src` governs and that cannot be nonce'd). Verify the smoke ScrollTrigger under **`next build && next start`**, NOT `next dev` — that is the exact meld trap (`next dev` cannot run under a CSP that forbids `unsafe-eval`). Record the final verified CSP string here when Task 1.3 lands.
- **Frozen `now` discipline (ADR-003) — non-negotiable.** `src/lib/clock.ts` exports one frozen reference instant shared by `getAvailability`, the date-strip "next 14 days", the UI, and all tests. **No `Date.now()` / `new Date()` / `Math.random()` in render or in the availability generator.** This is what keeps the date strip, the availability grid, the booking reference, and Playwright/Lighthouse runs reproducible. Same discipline as tape/meld.
- **`getAvailability` is pure and combo-uniform (ADR-003).** Signature `getAvailability({ barberId, serviceDurationMin, date })` in `src/lib/availability.ts`, no React. A combo is just a `Service` with a larger `durationMin` — no special case; the function finds a contiguous free block of `serviceDurationMin` against working hours − days off − lunch − seeded pre-bookings, and **emits colliding candidates as `{ available: false }` (not omitted)** so the grid renders accessible disabled slots. Half-open intervals `[start, start+dur)`. Must end at or before `close`.
- **`.ics` is hand-rolled (ADR-003) — no `ics` npm dependency.** Minimal RFC-5545 VEVENT `Blob` in `src/lib/ics.ts`; get timezone + line-folding right; build DTSTART/DTEND from the frozen clock's timezone. Test the output.

- **DECISION TO RE-EXAMINE — script `'unsafe-inline'` is present (ADR-002 said to avoid it "where the framework allows").** ADR-002's posture text aimed for `script-src 'self'` with NO script `'unsafe-inline'`. **In practice a bare `script-src 'self'` BLOCKS Next 15's unhashed inline bootstrap `<script>` elements (7 of them) and the next-themes flash-guard — which kills hydration entirely (app never mounts, so GSAP never even runs).** This is verified, not theoretical: the first headless run with `script-src 'self'` produced 7 `script-src-elem` violations, "Connection closed" page errors, and a non-hydrated tree. ADR-002's own escape clause ("a per-request nonce for Next's inline bootstrap IF NEEDED; `'unsafe-inline'` avoided WHERE THE FRAMEWORK ALLOWS") resolves to `'unsafe-inline'` here because the framework does NOT allow the strict form without per-request nonce middleware. So the Phase 1 CSP uses `script-src 'self' 'unsafe-inline'` — identical to meld's posture. **This is a conscious, documented relaxation, NOT drift.** The `unsafe-eval` ban (the GSAP-relevant part) is untouched. **reviewer / architect:** if you want the stricter script policy, the v1.1 hardening is per-request **nonce middleware** (a `middleware.ts` that generates a nonce, injects it into the CSP header AND into Next's inline scripts via the `nonce` mechanism), at which point both script and style `'unsafe-inline'` can drop. That is out of Phase 1 scope and carried as the **v1.1 CSP-nonce hardening debt** (covers BOTH `script-src` and `style-src` inline grants).

## Gallery early-pin bugfix — verified facts + the GSAP refresh-order rule (frontend-engineer, 2026-06-03)

Fixed the owner-reported "gallery odpala się jeszcze w trakcie services". The cross-agent rule that matters for ANY future GSAP-pinned section:

- **THE NEW RULE — async-loaded ScrollTriggers must refresh via the COORDINATOR, never in isolation, and the coordinator `sort()`s before `refresh()`.** `src/lib/gsap/refresh-coordinator.ts` is the single place that calls `ScrollTrigger.sort()` + `ScrollTrigger.refresh()`. Every `useGsapEffect` setup calls `requestGlobalRefresh()` on completion (the hook does this automatically — section authors get it for free). **Do NOT call `ScrollTrigger.refresh()` directly inside a section's setup** — that was the bug: each section refreshed in isolation, and because the hero pin is `{ idle: true }` (created LAST), a downstream pinned section (the gallery) that refreshed FIRST measured `start: 'top top'` against a document missing the hero's ~190vh pin-spacer, pinning ~1710px too early (inside services).
- **WHY `sort()` IS LOAD-BEARING (not just the debounce).** `ScrollTrigger.refresh()` recomputes triggers in their internal LIST order (= creation order by default), and a pinned trigger's pin-spacing only shifts the triggers that refresh AFTER it. With the hero created last, even a coordinated single `refresh()` left the gallery stale (verified: gallery `start` stayed 3788 vs the correct ~5498). `ScrollTrigger.sort()` reorders the list by `refreshPriority` then document position, so the upstream hero pin refreshes before the downstream gallery — making the result independent of which GSAP chunk resolved first. **The debounce alone is NOT enough; the `sort()` is the fix.** If you add another upstream pin, this stays correct (sort orders all pins by document position).
- **The coordinator also refreshes on `window` `load` (images/fonts settled) and on a debounced `resize` (200ms).** Verified resize at 1280/1680/1100 keeps the gallery pin start after the services bottom. ScrollTrigger has its own resize handling; the coordinated refresh keeps the `invalidateOnRefresh`-driven pin distances consistent across the whole list.
